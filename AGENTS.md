## Quick Rules

- **Code Exploring:** Use Glob/Grep for targeted searches. Read `PROJECT_STRUCTURE.md` first for the full architecture breakdown — this file only covers commands and policy.
- **Package Manager:** Use **Bun**, not npm, for everything in this repo (`bun install`, `bun run <script>`, `bun test`). A few scripts still shell out to npm as legacy/compatibility exceptions — see Canonical Commands below; don't take that as license to default to npm elsewhere.
- **Process Management:** NEVER kill processes directly. Use `npx kill-port {ports}`.
- **Task Completion:** Always ensure a successful build after changes (`bun run build`, plus `cargo build` for Rust changes).
- **Commits:** Commit on task completion. Follow the project's existing commit message style. NO "Generated with Claude Code" / "Generated by AI" signatures.
- **Testing:** Root Jest enforces an 80% coverage threshold (branches/functions/lines/statements) — but only over `src/`; `terminal-monitor/`, `mcp-server/`, `packages/*`, and E2E each own a separate test runner outside that gate (see Testing & Quality below). Run the relevant test(s) before committing.

## Repository Map

TermFlow core is a Tauri 2 (Rust) desktop app with a shared React renderer, plus several companion TypeScript packages/services. Full breakdown, file-by-file, is in `PROJECT_STRUCTURE.md` — this is the short version:

| Path | Purpose |
|---|---|

## Package Manager & Workspaces

- **Bun is canonical.** Root `bun.lock` + `bunfig.toml` (`linker = "hoisted"`, needed so `terminal-monitor`'s CRA/webpack toolchain resolves transitive deps). No root npm/yarn/pnpm lockfile.
- Root `package.json` declares Bun workspaces: `["terminal-monitor", "packages/*"]`. `agent-monitor` and `mcp-server` are **not** workspace members and keep their own lockfile/toolchain — `mcp-server` still uses Bun for its own scripts, `agent-monitor` and `terminal-kit` retain npm in places (npm-era lockfile / `postinstall/prepublishOnly` hooks).
- Known npm exceptions to be aware of, not to imitate elsewhere: root `test:all` = `npm run test && npm run test:e2e`; root `mcp:dev` shells to `cd mcp-server && npm run dev`; CI (`ci.yml`/`e2e-tests.yml`/`release.yml`) installs via `bun install --frozen-lockfile` but still runs `npm test`/`npm run build` for the actual run steps (not yet migrated to `bun run`).

## Canonical Commands

**Root (`termflow-core/`):**
```bash
bun install                      # Install deps
bun run dev                      # tauri dev — full app, renderer in watch mode
bun run dev:renderer             # Renderer dev server only (port 42010)
bun run build                    # build:terminal-core && build:renderer
bun run build:tauri              # tauri build --no-bundle (native binary only)
bun run publish:tauri            # tauri build (full bundle/installer)
bun run build:terminal-core      # Build @termflow/terminal-core (tsup, ESM+CJS)
bun run build:mcp-sidecar        # Compile mcp-server/ to a native sidecar binary
bunx tsc --noEmit                # Typecheck (also: bun run typecheck)
bun run test                     # jest (root unit tests)
bun run test:workspace           # bun --filter @termflow/terminal-core test
bun run test:e2e[:headed|:debug] # Playwright E2E (quarantined in CI, see below)
```

**Rust** — three separate manifests under `src-tauri/`: the Tauri app, `pty-host`, and `pty-protocol`.
```bash
cd src-tauri && cargo build && cargo test && cargo clippy
cargo build --manifest-path src-tauri/pty-host/Cargo.toml --release   # or: bun run build:pty-host
```

**Subprojects** — each owns its own scripts; `cd` in first:
- `mcp-server/`: `bun run build`, `bun run dev`, `bun test`, `bun run typecheck`
- `packages/terminal-core/`: `bun run build`, `bun run dev`, `bun test`
- `terminal-monitor/`: `npm start`/`build`/`test`/`test:e2e`/`lint`/`format` (own package, uses npm scripts even though it's a Bun workspace member)
- `agent-monitor/`: `npm run build`/`start`/`dev`/`watch`/`team:start <config>`/`team:session <config>`
- `terminal-kit/`: `npm run build`/`dev`

## Testing & Quality

- **Root Jest**: 80% threshold for branches/functions/lines/statements, scoped to `src/` only (`jest.config.js`). It does **not** cover `terminal-monitor/`, `mcp-server/`, `packages/*`, or E2E — those own separate runners and aren't held to this number automatically.
- **Playwright E2E** (`tests/`, `e2e-tests.yml`) is currently quarantined in CI (`continue-on-error`) pending a Tauri-specific rewrite — don't treat a red E2E run as a hard blocker, but don't ignore new failures either; flag them.
- **Rust**: `cargo test` + `cargo clippy` across all three manifests (app, `pty-host`, `pty-protocol`).
- There is **no enforced file-size limit** (no lint rule, no CI check). Treat "keep files reasonably small" as a maintainability guideline, not a hard rule.
- No root `lint` script exists (removed from CI). `terminal-monitor` has its own `lint`/`lint:fix`.

## Active Architecture & Features

This repo is well past "tabs + panes + a terminal." Before assuming a feature doesn't exist, check `PROJECT_STRUCTURE.md` and grep the renderer/backend — current major surfaces include:

- **Terminal engine**: `@termflow/terminal-core` shared xterm engine, xterm.js v6 + addons (fit, search, serialize, unicode11, web-links, webgl), Kitty/`modifyOtherKeys` keyboard protocol.
- **PTY layer**: native PTYs (`portable-pty`) plus tmux-backed terminals with WSL fallback; SQLite-backed scrollback/history persistence keyed by `tab_id`.
- **Layout & session**: layout persistence, multi-window detach/drag broker, session reconnect/resume (RDP/unlock, standby/resume glyph-atlas repair).
- **Canvas Mode**: a graph/node canvas view for terminals and their connections (backend + renderer support — see `PROJECT_STRUCTURE.md` for exact files).
- **Automation**: an automation editor/runtime with targeting, scheduling, validation, logs, and webhook providers.
- **Snippets**: snippet import/export and command-suggestion support.
- **Notifications**: unseen-output/activity tracking, notification chime, native OS notifications.
- **Network config**: LAN exposure toggle, auth token rotation, zero-downtime API hot-restart, cross-instance port-conflict detection.
- **Other**: in-terminal search, session recording/export, color schemes, per-surface zoom, accessibility (dialog focus-trap/mnemonics), URL/file/editor opening from terminal output.
- **Optional Pro/fabric integration**: `termflow-fabric` sidecar peering, Velopack update channel, Pro-only build config (`tauri.pro.conf.json`) — open-core boundary, don't assume every build includes it.

## MCP Server

`mcp-server/` is an **active**, tested MCP sidecar (`termflow-mcp-server`) exposing terminal tools (`list_terminals`, `create_terminal`, `execute_command`, `get_terminal_output`, `get_terminal_detail`, `get_my_terminal`, `close_terminal`) to AI clients over streamable HTTP.

- Self-identity: `get_my_terminal` / the `"me"` shorthand resolve via the `X-Termflow-Terminal-Id` header.
- Hardening: optional bearer-token auth (legacy env var name `AUTO_TERMINAL_TOKEN`, with `AUTO_TERMINAL_API_TOKEN` back-compat), constant-time compare, configurable bind host (`MCP_HOST`), parent-PID watchdog (`MCP_PARENT_PID`) that exits when the Tauri host dies, SSE idle-heartbeat to prevent stream disconnects, and an `AUTO_TERMINAL_INSTANCE_ID` in `/health` to distinguish sidecar instances.
- Built via `scripts/build-mcp-sidecar.mjs` (`bun build --compile`), launched by the Tauri backend as a sidecar (`src-tauri/build.rs` + capabilities scope).
